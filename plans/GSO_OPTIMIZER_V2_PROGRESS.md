## 1. Goal

Three coordinated re-architectures of the Genie Space Optimizer (GSO) plus a final cleanup pass, shipped as cross-reviewed PRs the human merges:

1. **Eval / judge / tracking v2 — DONE (Phases 1–6).** Make the official Databricks **Genie Benchmark (Eval-Run) API** the single authoritative evaluation runner; drive lever routing from its per-question `assessment_reasons`; retire the local judges, MLflow, and the Prompt Registry; make Delta the sole tracking/versioning store; migrate the Workbench UI to be assessment-centric.
2. **Orchestration v2 — REMAINING (Phases 7–9).** Replace the 6-notebook DAG with the **5-task controller-notebook design** in the arch doc: one `03_optimize` `while` loop whose **first attempt is a broad, measured, reversible coverage pass** (enrichment folded in) and whose later attempts are surgical, with benchmark repair inlined into `01` and `deploy` dropped. Split into three sequential phases — job skeleton + front-of-pipeline `00`/`01`/`02` + Delta schema (7) → the `03_optimize` two-mode controller loop, the riskiest core (8) → `publish_and_audit` + end-to-end gates (9).
3. **Workbench UI re-architecture — REMAINING (Phases 10–14).** Re-shape the Optimize tab from the 6-stage pipeline framing to a "run cockpit": a 5-task rail + the internal coverage/surgical attempt loop made legible (the Jobs UI now shows only one `03_optimize` task), plus the app-backend contract to expose `loop_state` / `attempt_mode` / `terminal_reason` / champion / publish-audit summary. Split into five sequential UI phases — backend contract (10) → config surface (11) → live cockpit (12) → resolution & trust (13) → drill-down & history (14). Depends on the orchestration phases' (7–9) new Delta artifacts.
4. **Cleanup / tests / docs — LAST (Phase 15).** A single final pass after the orchestration + UI reshapes land, so cleanup sweeps up dead code from ALL THREE efforts (retired scorers + the superseded notebooks/tasks + the retired 6-stage UI components), backfills tests, and refreshes docs.

## 3. Key findings (grounding)

### 3.1 Benchmark / Eval-Run API (databricks-sdk v0.102.0)
Under `/api/2.0/genie/spaces/{space_id}/eval-runs`:
- `genie_create_eval_run(space_id, benchmark_question_ids=None)` — empty/None ⇒ runs all questions in the space.
- `genie_get_eval_run` → `num_correct / num_done / num_needs_review / num_questions` + `eval_run_status`.
- `genie_list_eval_results` → per-question summaries; `genie_get_eval_result_details` → `assessment` (GOOD/BAD/NEEDS_REVIEW), `assessment_reasons` (`ScoreReason` ×25), `actual_response`, `expected_response`, `manual_assessment`.
- Accuracy = `num_correct / num_questions`, server-side.

### 3.2 Enum reference (`databricks.sdk.service.dashboards`)

- **`ScoreReason`** (25):

### 3.3 Reason → lever routing (implemented, Phase 3)
`rca._ASSESSMENT_REASON_TO_RCA_KIND` maps all 25 official reasons + the derived `ASSET_TYPE_MISMATCH` to an existing `RcaKind`; `levers_for_assessment_reasons` resolves levers by **reusing** the §0.4 `_RCA_KIND_TO_LEVERS` table (do NOT invent a new map). The deterministic SQL-shape RCA in `rca.py` runs alongside as the fine sub-router; its findings carry confidence `0.8–0.9` vs the coarse reason findings' `0.6`, so the structural diff wins on conflict for the same `(qid, lever)`. `EMPTY_GOOD_SQL` is non-actionable (GT-quality, not a Genie fault).

### 3.4 Eval-run budget (HARD 2-hour job cap)
Native eval-runs are async server jobs, materially slower than the retired in-process scoring: **~15–20 min per 30-question run**, scaling with space complexity, warehouse size, and question count. The DABs job has a **hard 2-hour wall** — total eval wall-clock, NOT iteration count, is the binding constraint.

- **Subset-first 3-gate (implemented, Phase 1):** slice (~5–10 failing-cluster Qs) → P0 (~10–15 priority Qs) → full only after slice+P0 pass. Selectors `eval_gates.select_slice_qids` / `select_p0_qids`; caps `SLICE_GATE_MAX_QUESTIONS=10` / `P0_GATE_MAX_QUESTIONS=15`. Most iterations must NOT run a full benchmark.
- **Budget math:** ≈17 min / 30 Qs ⇒ ~6–7 full runs fit in 2h. Fixed full runs ≈ 3 (baseline + the attempt-1 coverage eval + the publish/finalize full run), leaving ~60–69 min for the loop. `max_attempts` (3 — surgical only; coverage is a free probe) / `max_iterations` (5) is an upper bound, not a target; with coverage free, up to 3 surgical full runs fit comfortably in the residual budget.
- **Budget-aware cap (implemented):** `eval_budget` tracks cumulative official-runner wall-clock and stops the loop before an iteration that can't fund its gate cycle while reserving the final full run. Eval-runs are **sequential** (no API concurrency flag) — assume no parallelism.
- **Bounded working set (30–40 Qs)** keeps a single full run well under budget; preflight enforces the window.

### 3.5 Live-space benchmark mutation — provenance & cleanup (UI requirement)
GSO mutates the **user's live production space** benchmark set (additive PUSH of EXPLAIN-validated questions; PRUNE of invalid/SQL-erroring ones). This is now done in `00_intake_and_snapshot` + `01_benchmark_qc_and_repair` (was `preflight`). It must be **transparent in the Workbench UI**: show the benchmark **diff** (added / removed / changed).
- **Provenance ledger (Delta):** `genie_opt_benchmark_mutations(run_id, question_id, op ∈ {added,removed,changed}, before, after, reason)`, populated at the push/prune (`state.write_benchmark_mutations`). Served to the UI; also reconstructable as (current benchmarks) − (intake snapshot).
- **Cleanup = existing rollback:** the intake snapshot captures the ORIGINAL `serialized_space`. On **discard**, rollback re-PATCHes it (GSO additions removed); on **accept**, the champion config (incl. additions) persists. Merge-only publish never deletes user-authored rows.

### 3.6 Example-SQL leakage guard (EVAL-VALIDITY — hard constraint)
The benchmark is held-out *by nature* (Genie never sees the ground-truth just because the question lives in the space's benchmark config), so there is **no train/held-out split**; the whole set is scored each run. The one real leakage path is **GSO's own config patching**: writing a benchmark question's Q→SQL pair into the space's *Example SQL Queries* section lets Genie read the answer key at inference and fraudulently inflate the score.
- **Hard constraint:** every config write path that touches *Example SQL Queries* — the attempt-1 coverage pass's example-SQL seeding (old Lever 0) and any lever that emits example SQL — MUST exclude examples matching a scored benchmark item (by question-id AND normalized-SQL hash). **Seeding from *passing* rows is itself leakage** and must be excluded.
- **Implemented:** deterministic always-on `LeakageOracle.is_scored_benchmark_qa`; hard-blocks in `is_example_sql_benchmark_leak` regardless of config flags; unit-tested that no scored Q/A reaches the Example SQL config.

## 5. Open questions / risks
- [x] **`benchmark_repair_max_tries` (K) default — RESOLVED: K=3.** One **try** = one complete repair sweep over the benchmark set: (1) the model reviews every existing question (or synthesizes new ones if none exist, to reach the 30–40 window); (2) for each question that failed validation — EXPLAIN-invalid, contaminated, near-duplicate, or missing ground-truth SQL — it produces a repaired candidate (fixed SQL, corrected expected answer, dedup, or a replacement question); (3) the sweep re-validates via EXPLAIN. A try is **consumed** only when ≥1 question is still invalid after re-validation (the loop retries with the still-failing subset); the initial discovery validation that *finds* the failures is triage, not a repair try. Hard-fail `BENCHMARK_UNREPAIRABLE` only after 3 tries still leave ≥1 invalid question. Each sweep is an LLM pass + cheap EXPLAIN re-validation, so 3 is a reasonable bound; a set still broken after 3 is genuinely unrepairable.
- [ ] **Plateau / no-improvement safety stop** in addition to `max_attempts`? If yes, a `break` condition in the `03_optimize` loop (no DAG change). **Still deferred** (arch §13.2) — with `max_attempts=3` and coverage free, the loop is short enough that plateau-detection adds little; `max_attempts` + the eval-budget cap remain the only stops.
- [x] **Empty attempt-1 coverage pass — RESOLVED: fall through, do NOT consume a `max_attempts` slot.** `max_attempts` counts **surgical** attempts only; the attempt-1 coverage pass is a free probe (the "deliberate exception", arch §5.2) whether it produces nothing (warm/well-documented space) OR produces a patch that regresses and is rolled back. Concretely: coverage always RUNS (attempt 1) and always RENDERS in the UI (flat amber rung, `decision_reason="no_enrichment_candidates"` or `"rolled_back (Δacc<0)"`), but the next surgical attempt is attempt 2 with the full `max_attempts` budget intact. Rationale: with `max_attempts=3`, charging a slot for a warm-space no-op would waste a third of the budget on nothing; coverage is the deliberate exception, and making it free is consistent with that framing. The eval-budget cap (§3.4) independently bounds wall-clock, so a free coverage pass can't run away. (Complements the UI question below — empty coverage *renders* but does not *count*.)
- [x] **Ownership/scope of the net-new two-mode code — RESOLVED, then CORRECTED in Phase 8 (the original module homes named the WRONG files).** The two net-new pieces (arch §5.2) split by concern; the corrected homes, verified against the actual code while building Phase 8:
  - (1) **Per-attempt breadth/mode parameter + prompt threading → `optimizer._call_llm_for_adaptive_strategy`** (NOT `strategist.py`). `strategist.py` is a 56-line pure prompt-block *formatter* with no per-call signature — it cannot carry an `attempt_mode`. The mode signal is added as `attempt_no: int | None` + `attempt_mode: str | None` on `_call_llm_for_adaptive_strategy` (the single LLM chokepoint, optimizer.py ~9518), threaded into its `format_kwargs` and prepended as an explicit mode preamble to the prompt.
  - (2) **Invariant bypass → a parameterized `allow_cluster_agnostic: bool = False` escape hatch on `_call_llm_for_adaptive_strategy`** (NOT `invariant_policy.py`). `invariant_policy.py` is a generic `InvariantViolation` raise-vs-degrade handler; the one-source-cluster rule actually lives in THREE spots inside `_call_llm_for_adaptive_strategy` — the system-prompt scope-bound clause, the cross-namespace secondary drop, and the RCA defect-identity scope bound. All three are gated on `allow_cluster_agnostic` at that single chokepoint (NOT a scattered `if attempt==1`); coverage passes `True`, surgical keeps `False`.
  - (3) **Controller branch → the harness loop / `jobs/run_03_optimize.py`** (NOT `control_plane.py`). `control_plane.py` is intentionally I/O-free (no Spark/WorkspaceClient/LLM), and the loop must call `_run_enrichment`/`apply_patch_set`/the eval stage, so the loop body physically cannot live there. The harness owns the `while` controller; `control_plane.py` holds only the PURE helpers it dispatches on (`decide_attempt_mode`, `decide_coverage_outcome`, `decide_loop_terminal_reason`, `build_loop_state`) so the §5.1 control flow is unit-testable without a workspace.
- [x] **Delta schema reconciliation — RESOLVED (Phase 7 owns the DDL + migration).** ADOPT the arch doc's generic `genie_opt_artifacts` table, but scope it to **fat JSON handoff blobs that don't fit a per-attempt scored row**: `run_manifest`, `space_snapshot`, `benchmark_qc`, `triage`, `publish_record` (5 kinds — NOT `patch_bundle`/`targeted_eval`/`decision`/`loop_state`, which live in dedicated tables/columns). `genie_opt_iterations` is the **single per-attempt truth** — KEEP and EXTEND with the loop-state columns (`attempt_no`, `attempt_mode`, `best_accuracy`, `best_config_version_id`, `current_hypothesis` JSON, `do_not_repeat` JSON ARRAY, `terminal_reason`, `decision`, `decision_reason`) alongside Phase-4's `config_json`/`is_champion`; the UI Attempt Ladder/Ledger reads this one table, so **no separate `loop_state` artifact kind**. `genie_opt_patches` (structured patch rows; the "patch_bundle" = query by run_id+iteration) and `genie_eval_lever_loop_decisions` (per-proposal gating trace, finer than the per-attempt decision) are KEPT. **DROP the old 6-notebook tables no longer convertible:** `genie_eval_asi_results` (ASI judge, retired Phase 3/D2), `genie_eval_human_required` (MLflow human-review, retired Phase 5/D7), `genie_eval_proactive_corpus_profile` + `genie_eval_proactive_patches` (old enrichment sidecar, folded into 03 coverage), `genie_opt_finalize_attestation_matrix` (old finalize attestation → `publish_record` artifact), `genie_opt_suggestions` (old suggestions output → artifacts), `genie_eval_question_regressions` (subset-gate regression tracking; Phase 8 retires the subset gate), `genie_eval_gt_correction_candidates` (bespoke; fold GT-correction candidates into the `benchmark_qc` artifact), and `genie_opt_data_access_grants` (defined but only referenced in `run_preflight.py` comments — fold into `space_snapshot` or drop after confirming no runtime writer). - [x] **(UI) Champion truth source — RESOLVED.** The cockpit reads the explicit `is_champion` flag (Phase-4) as the authoritative champion rather than re-deriving `idxmax(accuracy)` in the UI (`compute_run_scores`). Phase 10 exposes both the flag and the per-attempt decision+reason.

Transparency over tidiness: the user sees the coverage pass ran and produced nothing, rather than a confusing gap. (The *separate* budget question — whether an empty coverage pass consumes a `max_attempts` slot — stays open below as a Phase 8 concern.)
