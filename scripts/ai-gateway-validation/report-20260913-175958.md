**What this means for the design:**

1. **BYOK is drop-in on the workbench's own path.** A customer's own Model Service answers on
   `/ai-gateway/mlflow/v1/chat/completions` with the standard OpenAI shape — **no Responses↔chat
   adapter is required.** The only picker change is accepting **arbitrary 3-level UC model ids**
   (`catalog.schema.name`); the `system.ai.*` strip rule does NOT apply to BYOK names.

2. **Reasoning-model tool constraint is real and must be handled.** When a customer points a Model
   Service at a *reasoning* model (here `gpt-5.6-sol`), function tools on `/chat/completions` require
   `reasoning_effort:"none"`, else a hard **400**. Create Agent is tool-heavy, so the client seam must
   send `reasoning_effort:"none"` on the tool path (or fall back to `/responses`). This is **not**
   observed on `system.ai.gpt-5-4`/`gpt-5-2` (they take tools with no reasoning_effort), so it is
   **model-version-specific** — the spec must not assume all GPT-family models behave alike.

3. **Auto-enumeration of custom Model Services is a gap.** Neither `serving-endpoints list` nor UC
   `registered-models` returns the object, and the obvious `ai-gateway/model-services` list endpoints
   404. Until the correct list API is identified, **BYOK model ids must be user-configured** (a
   text/config field per space or in settings), not auto-populated in the picker. Auto-discovery is a
   fast-follow pending the right API — it does not block the attribution feature.

### Implementation plan (regression-first, single-seam)

**Guardrail:** ship behind `GENIE_LLM_ROUTE={classic|gateway}` (default `classic`), so every step is a
no-op until explicitly flipped, and rollback is one env var. Because attribution is unavailable on the
classic path, the route swap and the tag header ship **together** — you cannot decouple them.

- **Phase 1 — route seam + tags (the unit that delivers attribution):** introduce ONE client factory
  that resolves base URL + model name + the `Databricks-Ai-Gateway-Request-Tags` header from
  `GENIE_LLM_ROUTE`, and is consumed by all 4 call sites — `llm_utils.call_serving_endpoint`,
  `create_agent._stream_llm`, and GSO `get_openai_client` (covers `call_llm` + `optimizer_utils`).
  Gateway base = `/ai-gateway/mlflow/v1`; model = mapped `system.ai.*`; tag =
  `{"application":"genie-workbench","component":<feature>}`. Classic remains the flag-off fallback.
- **Phase 1b — embeddings (5th site, now validated):** `leakage.get_embedding` uses the SDK
  `serving_endpoints.query()`, a *different* surface from the 4 chat sites. Under the flag it moves to
  `/ai-gateway/mlflow/v1/embeddings` with the same strip-rule name (`system.ai.gte-large-en`, dim=1024
  confirmed) and the same tag header. Ships with Phase 1 for full attribution but is a separate diff.
- **Phase 2 — model catalog + BYOK (S9):** `model_catalog` maps curated → `system.ai.*` (validated
  table above) AND accepts **arbitrary 3-level UC model ids** for customer Model Services (the strip
  rule does not apply to those). Since auto-enumeration of Model Services is a gap (S9-5), BYOK ids are
  **user-configured** (settings/per-space field), not auto-listed — auto-discovery is a fast-follow
  once the correct list API is found. The tool path must send `reasoning_effort:"none"` (S9-2b) so
  reasoning-backed BYOK models don't 400 on Create Agent's function tools.
- **Phase 3 — governance UX:** the entitlement failure mode is a **404, not a 403** (validated: an
  un-entitled SP gets `NOT_FOUND` on a Model Service an entitled user calls fine — the gateway hides
  what you can't access). So the downgrade logic must treat a **404 on a model the app believes is
  configured** as "not entitled / unavailable → `suggest_only`", NOT as a hard error — and it cannot
  key entitlement on 403. This collapses onto the same handler as unknown-model (S6). UX copy should
  say "model unavailable or access not granted" (the two are indistinguishable at the HTTP layer).
  Separately, distinguish gateway-unavailable (region/preview) → automatic classic fallback.
